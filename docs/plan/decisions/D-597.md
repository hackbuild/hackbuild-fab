### D-597 R1-rails-registries-07 freezes the constants id order, not the prefix order

| field | value |
|---|---|
| Status | decided |
| Decision | Taken by the agent under owner delegation on 2026-10-20. `packages/profile/data/constants.json` is generated by `tools/gen/registries/constants.mjs` from `packages/profile/data/constants/<prefix>.json` (42 files) and `_head.json`, whose `order` freezes the 234 ids in the order the file held at the split. Frozen ids come first in that order; every later row follows sorted by id, whatever its prefix. The brief asked for a frozen prefix order with rows in file order; that was not taken. A row whose prefix is not its file name, an id without a prefix and an id listed twice are refused. `tools/legacy/inventory.json` was rewritten with `node tools/legacy/inventory.mjs --write`, since the fragment files cite legacy paths (8 rows, readers only). |
| Rationale | Today's rows are not grouped by prefix (51 prefix runs over 42 prefixes, measured), so a frozen prefix order would reorder the live array and break the brief's own parse-equal test; the frozen id list keeps the gathered file deep equal to the one it replaces. It is the order rule the checks seed already uses (`frozenThenSorted` in `tools/gen/lib.mjs`). |
| Evidence | Gathered object deep equal to `git show cae984a:packages/profile/data/constants.json` (measured); 21 values change byte form only (`3.0` to `3`). `node --test tools/test/constants-fragments.test.mjs` 9 pass; with the frozen order dropped 3 fail (measured). `npx vitest run packages/profile core/test/constraints-query.golden.test.ts packages/checks/test/capacitive-ceiling.test.ts` 137 pass 6 skip (measured). |
