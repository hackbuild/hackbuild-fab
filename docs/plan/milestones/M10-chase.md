# M10 chase

Version 4, 2026-10-04, revised 2026-10-05 for the originals (D-222). Part of the hackbuild-fab plan set; PLAN.md is the index.

Goal: Designs as data. Six shipped designs (KNURL, STYLUS, BLOCKS,
KEYWAY, OGEE, PIP) render from a chase plus build.ts with no bespoke UI
beyond declared slots; KNUCKLE and TENON build as the first post-plan
designs; the PIP replica fits inside a declared glue budget; chase.validate
returns typed questions.
Depends on: M06, M09 (and through them M00 to M05)
Adopted dependency: zod 4.6.5, for the derived chase schema (MILESTONES.md 1.2, D-040)
Commands added: chase.scaffold, chase.validate, chase.diff, chase.patch, chase.render, chase.bake (MILESTONES.md 1.3)
Release at exit: baked benches for the six designs as GitHub release assets with their sha256, when the owner asks (D-034, owner default)

hbf (working name) is the binary with CLI, MCP and HTTP transports.
CHASE (working name) is the typed design document. STYLUS (working name,
was FEELER) is the printed sensor design. PIP (was HAFT) is the published
print-in-place controller at hackbuild/pip-controller (D-013).
tools.hack.build (proposed) is the cookieless bench origin of D-034. Every
number in this file carries a qualifier (measured, computed, vendor,
inferred, unknown) or names the file it was counted from (D-007). Numbers a
legacy bench printed are "computed by the legacy bench": the bench did the
arithmetic, nobody measured a print. Counts are as of 2026-10-04 and are
generated by tools/counts.mjs from M-1 onward (D-010). Repo paths are
relative to the hackbuild-fab root; evidence paths are absolute. "Bench" is
the internal word for the layout a chase renders into; user-facing copy
uses the tool name.

## What this milestone proves

Before M10, references carry a `chase.ts` typed against spec/chase.ts with
no runtime chase package (M00 to M06), and M09 renders a rail from
ParamField declarations for the `single` and `composer` kinds. M10 makes
the chase a package: `defineChase` and `defineBuild` with `ParamsOf`, a
zod schema derived from the declarations, schema version 2 with
migrations, a deep normalise on load, a validator that returns
`CommandError[]` and typed questions, and the six author commands.

The proof is the corpus. Six designs that shipped as hand-written benches
render from a chase plus build.ts on the shared kernels, each reaching the
parity triple against its legacy file and the five design tests (D-152).
The UI each one needs beyond the generated shell lives in declared slots,
and a counter proves it. PIP is the acceptance replica: the GUIDELINES 7b
pattern applied to fab, with a glue budget declared before the work and
counted after.

The owner's original benches are the bar (D-222). A re-hosted bench is
accepted only when it matches its original's UX as the design's record
states it: the same steps and step behaviour, the same drive (pad, readout
bar, sliders or live controls, whichever the original has), the same
readouts with their wording and units, and the same lit 3D views, cams,
toggles and poses. The gold checklist of gold-standard.md section 11
(D-212) is a floor every bench also passes; passing it does not show UX
parity. The UX of record for each design is the "UX anatomy" section of
`knowledge/designs/<slug>.md` and the original's shots under
`fab-knowledge:originals/<slug>/shots/`,
summarised in "Original UX of record" below. The quarantined mockups under
`fab-knowledge:mockups/` are never a
target, a layout source or a comparison image.

KNUCKLE and TENON are the first designs written after the Sep 18 plan.
They admit the feature kinds the corpus kept building without a home
(thread, bayonet, magnet, insert) and give KNUCKLE the headless kernel
D-045 asks for.

## M10-T02 The chase package: defineChase, defineBuild, ParamsOf, derived schema

Goal: a chase is a type-checked TypeScript module whose params type flows
into build.ts, whose runtime schema is derived from the same declarations,
and whose source holds declarations only.

Inputs:
- spec/chase.ts (Chase, ChaseMeta, ParamField, ParamGroup, ShowWhen, Preset, ExportDecl, ParamsOf; D-132)
- fab-knowledge:synthesis/api-library-ai-design.md sections 8.1 to 8.5
- reference/keys/flex-pair/chase.ts and build.ts (M05)
- every `reference/*/*/chase.ts` written in M00 to M06 (typed object literals with no runtime package)
- `x/tsc/m10/snippet.ts` (the ParamsOf form, compiled 2026-10-04)

Steps:
1. Wire zod 4.6.5 first: `packages/chase/src/schema.ts` derives one zod
   schema per chase from its ParamField declarations (numeric fields as
   `z.number().finite()` inside `range` with `step` checked, enum from
   option values, list as an array of the item object between `min` and
   `max`, derived fields absent from inputs) and derives JSON Schema from
   it for MCP and docs. The derived schema is a function of the chase
   value, so a chase edit changes it without a hand-written schema.
2. `defineChase<const C extends Chase>(c: C): C` returns its argument
   unchanged at runtime and preserves literal types. `defineBuild(chase,
   fn)` types `fn` as `BuildFn<ParamsOf<C>>`. `ParamsOf<C>` flattens field
   ids across groups, maps `mm`, `deg`, `ratio`, `int`, `number` to
   `number`, `bool` to `boolean`, `enum` to the union of option values,
   `text` to `string`, `list` to an array of its item record, and omits
   `derived` (the form in `x/tsc/m10/snippet.ts`). A typo in a param name
   or a read of a derived field fails `tsc`.
3. Field ids are unique across groups and inside each list item; the
   validator returns E_SCHEMA naming both pointers on a clash, because
   `ParamsOf` flattens them.
4. Declarations only (standard rule 1). `packages/chase/src/declares.ts`
   reads the chase source and accepts: import declarations; one exported
   `defineChase({...})` call; object, array, string, number and boolean
   literals; unary minus on a number literal; identifiers and spreads that
   refer to imported constants (a registry package exporting a declared
   `ParamGroup`, for example an archetype's field set). It rejects every
   other call, arrow and function expressions, conditional, binary and
   logical operators, template literals with substitutions, loops and
   computed keys, each as E_SCHEMA with the source line and the JSON
   pointer of the enclosing field. Use the TypeScript 7.0.2 compiler API
   when the pinned package exposes one; when it does not, the card adds a
   parser, pins it exactly and lists it in the PR body for the D-040
   re-date.
5. Registry-validated strings (D-132, plan-deltas R90): `ExportDecl.kind`
   resolves in the exporter registry, a panel reference in the panels
   registry, every check id in `expect` and `waive` in the check
   registry, every `constraintDim` in the constraint registry, every
   `machines[]` id and material in profile. A check id that resolves to
   nothing refuses to render with E_REF and `didYouMean` (v3 section 13:
   never silently skips). A chase never selects checks: the registry runs
   every check whose appliesTo matches the Part IR (D-173). A waiver with
   an empty reason is E_SCHEMA; a waiver on a critical check is E_SCHEMA
   naming D-067. Gating comes from `ExporterDef.fabrication`, never from
   the chase.
6. `@hackbuild/kernel/author` re-exports `defineChase`, `defineBuild` and
   `ParamsOf`. Rewrite every existing reference chase.ts to call
   `defineChase` and every build.ts to call `defineBuild`; their goldens
   must not move (a moved defHash is a failure of this card).

Files to create:
- packages/chase/package.json (private, MIT, author Moheeb Zara <hackbuildvideo@gmail.com>, dependency zod 4.6.5 exact)
- packages/chase/src/define.ts
- packages/chase/src/params-of.ts
- packages/chase/src/schema.ts
- packages/chase/src/declares.ts
- packages/chase/src/resolve.ts
- packages/chase/test/params-of.test-d.ts (type tests with `@ts-expect-error` for a param typo, a derived read, an enum value outside the options)
- packages/chase/test/schema.test.ts
- packages/chase/test/declares.test.ts
