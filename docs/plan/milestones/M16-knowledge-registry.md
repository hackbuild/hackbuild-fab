## What this milestone proves

The knowledge README names the ratchet: a lesson that proves right and
repeatable becomes a check, and the model's role for it drops to zero
(`knowledge/README.md`, copied at M-1-T13). M04 gave every check an origin
record and M12 made the records searchable. M16 closes the loop in both
directions: a record knows which checks enforce it, a check knows which
record explains it, and a symbol a record uses is defined before the record
uses it. The OGEE latch identity is the test case, because the seeded
record used LUG_TOT without defining it and CHK-MOT-05 could not run.

The registry becomes data a script can gate. `registry/tools.json` gains
the D-158 fields, the post-plan designs get rows, every row with harvested
files gets a legacy folder with sha256 and a lineage README, names live in
`knowledge/names.json`, and a slug gate refuses a new name that is taken,
banned or rejected. The 157-entry BENCH catalogue joins the fab registry as
one dataset filterable by scope. The check origins become the source data
for the failure-of-the-week posts, which a person publishes outside the
repo.

## M16-T01 Symbols first: record format and the defined-first lint

Goal: every identity in a knowledge record uses only symbols defined above
it in the same record, and a lint fails the build when one is not.

Inputs:
- knowledge/ (copied at M-1-T13 from `fab-knowledge:evidence/x/plan-to-refine/handoff/hbf/knowledge/`)
- knowledge/INDEX.json and packages/knowledge/src/index-records.ts (M12-T07: record id `<file stem>#<anchor>`)
- `fab-knowledge:sources/plan/knowledge-tiers.md` lines 1871 to 1872 and 1904 to 1905 (record LUG_TOT and the cam budget derivation)
- `fab-knowledge:evidence/x/tsc/m16/tool-registry.ts` (`SymbolDef`, `definedFirst`, compiled 2026-10-04)

Steps:
1. Fix the format. An identity is a fenced block with the info string
   `identity`. The symbols it uses are rows of a table above it whose
   first column is the symbol and whose columns are: symbol, definition,
   value, unit, qualifier, source. A derived symbol's definition is an
   expression in symbols already in the table.
2. Add `SymbolDef` to `spec/tool-registry.ts` exactly as in the compiled
   snippet: `symbol`, `definition`, `value` (number or null), `unit`
   (`mm`, `deg`, `1`), `qualifier` (the D-007 qualifiers plus `design
   value`), `source` (absolute path and line).
3. Write `packages/knowledge/src/symbols.ts`: parse every record's
   definition tables into `SymbolDef[]` keyed by record id; run
   `definedFirst(record, lines, table)` over every record, where `table`
   holds symbols defined by records the current record links to with
   `see <record id>`. Any UPPER_SNAKE token in an identity block that is
   neither in the record's tables above the block nor in a linked record is
   a finding with record id, symbol and line.
4. Write `knowledge/symbols.json` (generated; sorted by record id, then
   symbol). The CI derived job regenerates it and fails on any diff.
5. Convert the other identity blocks the knowledge files already hold to
   the format: search `knowledge/` for code fences containing `=` between
   UPPER_SNAKE tokens and list them in the PR; convert those whose symbols
   a source file defines, cite the file and line; leave the rest in a plain
   fence and list each in `knowledge/symbols-gaps.md` (generated) with
   what is missing. A missing definition is never invented (D-180).

Files to create:

- packages/knowledge/src/symbols.ts
- packages/knowledge/test/symbols.test.ts

- packages/motion kinematics port of `kin_block.js` and `kin.py` (M07; lineage.json row for OGEE16 `kin_block.js`)

- packages/mechanisms `displacement-coincidence-latch` (M06-T05 step 2)
- `fab-knowledge:evidence/x/plan-to-refine/handoff/hbf/knowledge/kernels/motion-latch.md` lines 87 to 101 and `01-invariants.md` line 146 (the seeded text)

Steps:
1. Write `packages/motion/src/latch.ts` with `latchIdentity(p)` as in the
   compiled snippet, taking its parameters from the ported OGEE16 params
   (never retyped) and returning LUG_TOT, CAM, CAMLIFT, RISE_HALF, margin,
   overshoot, the general right-hand side and the seeded right-hand side.
   Its test asserts, on R16 params, margin and overshoot equal to the
   M07 kinematics' half select margin and full select overshoot within
   1e-9 mm, so the record and the motion program cannot drift apart.
2. Replace the section "The governing identities" in
   `knowledge/kernels/motion-latch.md` with the section below, anchored
   `latch-identity`. The numbers in its tables are written by
   `tools/knowledge/latch-numbers.mjs` from `latchIdentity()` between the
   markers `<!-- latch:begin -->` and `<!-- latch:end -->`; the derived
   job fails on a diff.

   ````markdown
   ## Latch identity {#latch-identity}

   OGEE latches a pin when the rod's lug clears the latch plate. The
   symbols below are defined before the identity uses them. Values are
   OGEE R16 design values from params.scad in ogee16-source.zip, or
   computed from them by kin.py.

   | symbol | definition | value | unit | qualifier | source |
   |---|---|---|---|---|---|
   | T | sheet thickness; the latch plate is one sheet | 3.0 | mm | design value | params.scad:18 |
   | LUG_H | height of the lug's flat retaining band | 0.60 | mm | design value | params.scad:82 |
   | LUG_RAMP | height of the lug's lead-in ramp, on top | 1.20 | mm | design value | params.scad:83 |
   | LUG_TOT | LUG_H + LUG_RAMP, the lug's full height | 1.80 | mm | design value | params.scad:84 |
   | STROKE | full travel of a row or column bar | 9.0 | mm | design value | params.scad:43 |
   | R_LATCH | rod rise at which the lug's flat face reaches the plate top | 7.6 | mm | design value | params.scad:71 |
   | C | half the rocker span between the pivots | 9.0 | mm | design value | params.scad:40 |
   | CROWN_OFF | crown arc centre past C along the rocker | 0.50 | mm | design value | params.scad:62 |
   | PIN_W | rod width | 10.0 | mm | design value | params.scad:80 |
   | LUG_P | lug projection past the rod | 1.25 | mm | design value | params.scad:81 |
   | NOTCH_W | foot slot width | 4.45 | mm | design value | params.scad:85 |
   | PIN_PLAY | (NOTCH_W - T)/2 | 0.725 | mm | computed | params.scad:86 |
   | SLOT_E | plate slot edge from the rod axis | 6.05 | mm | design value | params.scad:93 |
   | RAMP_A | foot ramp angle | 40 | deg | design value | params.scad:88 |
   | CAM | (PIN_W/2 + LUG_P + PIN_PLAY) - SLOT_E, lateral travel to pass the plate edge | 0.925 | mm | computed | params.scad:96, kin.py:89 |
   | CAMLIFT | rise the rod gains on the RAMP_A ramp while cammed aside by CAM | 0.776 | mm | computed | kin.py:90 |
   | RISE_HALF | (C + CROWN_OFF) sin(atan2(STROKE, 2C)), crown rise with one bar at STROKE | 4.2485 | mm | computed | kin.py:61 to 71 |

   margin is how far the half selected lug top stays below the plate top;
   it must be positive, or half select latches. overshoot is how far the
   fully selected lug's flat face rises past the plate top; it must be
   positive, or full select fails to latch.

   ```identity
   margin             = R_LATCH - RISE_HALF - CAMLIFT - LUG_TOT
   overshoot          = STROKE - R_LATCH
   margin + overshoot = STROKE - RISE_HALF - CAMLIFT - LUG_TOT
   ```

   On R16: margin 0.7753, overshoot 1.4000, both sides 2.1753 mm
   (computed). Where the crown sits midway between the pivots, RISE_HALF is
   STROKE/2 and the identity reads
   ````
