## M12-T01 Wire the MCP stack and prove transport parity

Goal: `hbf mcp` serves every registered command over MCP 2026-07-28 on
@modelcontextprotocol/server 2.3.0, statelessly, and each tool returns the
same CommandResult the CLI prints with `--json` for the same inputs.

Inputs:
- core/src/registry.ts, core/src/result.ts, core/src/text.ts (M00-T13)
- spec/commands.ts (`CommandName`, `McpToolName`, `CommandDef`, `CommandResult`, `McpToolDef`), spec/errors.ts
- `fab-knowledge:research/ai-tooling-and-api-design.md` sections 2.1, 2.2
- `fab-knowledge:synthesis/verified-claims.md` C10
- `fab-knowledge:evidence/x/plan-to-refine/handoff/hbf/scaffold/core/package.json` (stale: `@modelcontextprotocol/sdk ^2` and `zod ^3`; replaced here)

Steps:
1. Check the pins against the registry on the day the card starts:
   `npm view @modelcontextprotocol/server version dist-tags` and the same
   for `@modelcontextprotocol/core`. Pin both exactly in core/package.json
   (D-040 pins 2.3.0 for both; a newer 2.x moves only with a re-dated row
   in PLAN.md section 16 and ../PACKAGES.md, D-040). Remove
   `@modelcontextprotocol/sdk`. Import zod as `zod/v4` from zod 4.6.5.
2. Wire the dependency before own code (MILESTONES.md rule 1): a
   throwaway server with one read tool (`constraints_query`) answering one
   call from the SDK's own client over stdio. Record the call and response
   in `core/test/fixtures/mcp/first-call.json`.
3. `core/src/mcp/server.ts` builds the tool list from the CommandDef
   registry and the table in M12-T02. One tool handler per McpToolName
   dispatches to the CommandDef `run` of the covered command its selector
   names (`MCP_TOOLS[].selector`; for example `check_run` with `report:
   "fits"` runs fits.table, `layout_solve` with `op: "nest"` runs
   nest.pack, D-193). Before routing, a field that is null, absent, false,
   an empty string or an empty array counts as absent.
   The tool's input schema is derived from `McpToolIO[tool]` in
   spec/commands.ts: the selector, `cursor` and every covered command's
   fields. After routing, the handler passes the chosen command exactly its
   own CommandIO input (`McpRoute`) and validates it with the CommandDef
   zod schema, so the CLI and MCP share one validator; a non-absent field
   that only another covered command owns is E_SCHEMA. The zod schema
   carries the chase.scaffold `kind` and `from` docs as `.describe()` text
   (spec/commands.ts). The registry applies `resultOk` to every run()
   result; a command never sets `ok`.
4. Stateless: no initialize handler state, no session map, no in-memory
   cache that changes a result. Every handle is an `hbf://` URI into
   `<workspace>/.hbf/store/` (D-050). `workspace` comes from the server
   argument `--workspace`, never from a tool argument (api-library-ai-design
   5.3 `CommandCtx.workspace`).
5. Each result carries `structuredContent` = the CommandResult and one text
   block holding the text mirror (api-library-ai-design.md 6.3). Every tool
   declares an `outputSchema` derived from the CommandResult zod schema.
6. Transport parity test: for every reference under reference/ with an
   `expected/report.json`, run the CLI with `--json` and the MCP tool with
   the same arguments through the SDK client over stdio; compare the
   RFC 8785 canonical JSON of both CommandResults with `inputsHash` and
   `buildHash` included. Bytes must be equal.
7. `hbf mcp --workspace <dir> --tools <profile>` starts the stdio server.
   `--http <port>` starts Streamable HTTP on 127.0.0.1 only (M12-T03).

Files to create:
- core/src/mcp/server.ts, core/src/mcp/handlers.ts, core/src/mcp/schema.ts
- core/src/commands/mcp.ts (utility verb)
- core/test/mcp-parity.test.ts
- core/test/fixtures/mcp/first-call.json

Acceptance:
- `npm ls @modelcontextprotocol/server @modelcontextprotocol/core` prints 2.3.0 for both (or the re-dated pin) and `npm ls @modelcontextprotocol/sdk` prints nothing; exit 0.
- `npm test -w core -- mcp-parity` exits 0: CLI and MCP canonical CommandResults byte-equal for every reference with an expected report.
- `npx --no-install hbf mcp --workspace . --tools all` answers a `server/discover` request on stdio (M12-T09) and a `tools/call` for `constraints_query` without any prior request; exit 0 on stdin close.
- `grep -rn "Mcp-Session-Id\|sessionId" core/src/mcp` returns nothing.

Done when: a model connected over MCP and a person at the CLI get the same
evidence for the same call.

   test imports those, never a hand copy.

| check failures | `isError: false`, `verdict: "fail"` | 1 | 200 |
| E_SCHEMA, E_REF, E_HANDLE, E_STALE, E_PARAM_MISSING | `isError: true`, structuredContent = CommandResult | 2 | 422 |
| E_UNSAT | `isError: false`, `verdict: "fail"`, Interval with every bound in `result`, `next` naming the binding fact | 1 | 200 |
| skip only | `isError: false`, counted in `counts.skip` | 0 | 200 |
| E_KERNEL | `isError: true` with the knowledge record id | 1 | 200 |

| E_GATE (declined, expired, forged, replayed) | `isError: true` | 3 | 403 |
| E_REPEAT | `isError: true` | 5 | 429 |
| unknown tool, malformed request, crash | JSON-RPC error | 70 | 500 |

2. Tasks (D-108): a client that declared `io.modelcontextprotocol/tasks`
   in its per-request capabilities gets a `CreateTaskResult` for `always`
   tools and for `over2s` tools whose run passes 2 s; any other client gets
   a synchronous result. A task that finds a clash or a failing check ends
   `completed` with a fail verdict; `failed` carries a JSON-RPC error only.
   Cancellation (`tasks/cancel`) aborts `CommandCtx.signal`, which cancels
   the manifold ExecutionContext (D-055). A task is never returned to a
   client that did not declare the extension.
3. HTTP transport: `hbf mcp --http <port>` binds 127.0.0.1 and serves
   Streamable HTTP MCP at `/mcp` and the plain JSON command endpoint at
   `POST /v1/<command>` with the status codes above. It writes a random
   bearer token to `.hbf/http.token` (mode 0600) and prints only that path
   and the token fingerprint (first 4 and last 4 characters), never the
   token (D-009). Both endpoints refuse a request without it (401). The
   FAB app's vite.config.ts reads `.hbf/http.token` at start and its dev
   proxy adds the Authorization header to `/v1` and `/mcp`, so the token
   never reaches stdout or the browser. This launcher and the token are
   this card's default; D-106 lists no serve verb (open items).
4. Text mirror: one renderer in core/src/text.ts serves the CLI, the MCP
   text block and the FAB console tab. Order: status line, findings (fail
   first, then warn; passes counted only), errors, next.

Files to create:
- core/src/mcp/map.ts, core/src/http/server.ts, core/src/http/auth.ts
- core/test/transport-map.test.ts, core/test/tasks.test.ts, core/test/http.test.ts

## M12-T04 Export gate over MCP and HTTP

Goal: a fabrication export asks a person through the host on every
transport, the approval is bound to the build the person saw, and the six
named attacks and mistakes all write nothing.

Inputs:
- core/src/tty-gate.ts (M00-T13: the CLI gate with TTY, no bypass flag)
- `fab-knowledge:synthesis/api-library-ai-design.md` 6.5
- `fab-knowledge:research/ai-tooling-and-api-design.md` 2.3
- `fab-knowledge:synthesis/verified-claims.md` C10 (requestState row)
- `.claude/settings.json` (M-1-T04: `ask` on `mcp__hbf__export_run`)

Steps:
1. `core/src/gate.ts` mints and verifies requestState per D-109. The
   claim binds command, args digest, build hash, a 10-minute expiry and a
   single-use nonce. argsDigest is sha256 of RFC 8785 JSON of the args
   with requestState removed and every null or false-default field
   dropped: `requestState` and `inputResponses` never enter the digest, and
   a field whose value is null or false is left out (every boolean
   argument of a gated command defaults to false), so `dryRun: false`,
   `dryRun` absent and `machine: null` beside a set machine never change
   the digest. The args are the routed export.run input (`McpRoute.input`
   in spec/commands.ts), so the `op` selector of `export_run` and the
   nullable nest.pack fields an MCP call carries never enter the digest,
   and an MCP call and the CLI line for the same export digest the same.
   The snippet type-checked with TypeScript 7.0.2 strict on 2026-10-04.

```ts
// core/src/gate.ts
import { createHash, createHmac, randomBytes, timingSafeEqual } from "node:crypto";

/** Keys in RFC 8785 order, so JSON.stringify of this literal shape is canonical. */
export interface GateClaim {
  /** digestArgs of the command args: requestState and inputResponses removed, null and false fields dropped. */
  argsDigest: string;
  /** buildHash the person was shown. */
  buildHash: string;
  /** CommandName, e.g. "export.run". */
  cmd: string;
  /** Expiry, ms since epoch: issue time plus 600000 (10 minutes). */
  exp: number;
  /** 16 random bytes, base64url. */
  nonce: string;
}

export type GateCheck =
  | { ok: true; claim: GateClaim }
  | { ok: false; reason: "malformed" | "forged" | "expired" | "replayed" | "args-moved" };

/** Persisted single-use set: one JSON line per used nonce in .hbf/gate-used.jsonl. */
export interface NonceLedger {
  /** Atomic across processes: true when this call recorded the nonce, false when it was already present. */
  consume(nonce: string, exp: number): boolean;
}

export const GATE_TTL_MS = 600_000;

export function canonicalClaim(c: GateClaim): string {
  return JSON.stringify({ argsDigest: c.argsDigest, buildHash: c.buildHash, cmd: c.cmd, exp: c.exp, nonce: c.nonce });
}

/**
 * argsDigest: sha256 hex of RFC 8785 JSON of the args with requestState and
 * inputResponses removed and every null or false field dropped. Gated
 * commands take flat args, so only the top level is pruned. `canonical` is
 * the RFC 8785 serializer the store uses for inputsHash.
 */
export function digestArgs(args: Readonly<Record<string, unknown>>, canonical: (v: unknown) => string): string {
  const kept: Record<string, unknown> = {};
  for (const [k, v] of Object.entries(args)) {
    if (k === "requestState" || k === "inputResponses" || v === null || v === false) continue;
    kept[k] = v;
  }
  return createHash("sha256").update(canonical(kept)).digest("hex");
}

export function newNonce(): string {
  return randomBytes(16).toString("base64url");
}

export function mintState(c: GateClaim, key: Buffer): string {
  const body = Buffer.from(canonicalClaim(c)).toString("base64url");
  const mac = createHmac("sha256", key).update(body).digest("base64url");
  return `${body}.${mac}`;
}

/**
 * Order matters: MAC first (forged), then shape (malformed), expiry, args, nonce.
 * args-moved is checked before the nonce is consumed, so a state minted for other args is not burned.
 * The build hash is compared by the caller after a fresh build: a moved hash re-asks.
 */
export function verifyState(
  state: string,
  key: Buffer,
  nowMs: number,
  ledger: NonceLedger,
  expect: { cmd: string; argsDigest: string },
): GateCheck {
  const parts = state.split(".");
  const body = parts[0];
  const mac = parts[1];
  if (parts.length !== 2 || body === undefined || mac === undefined) return { ok: false, reason: "malformed" };
  const want = createHmac("sha256", key).update(body).digest();
  const got = Buffer.from(mac, "base64url");
  if (got.length !== want.length || !timingSafeEqual(got, want)) return { ok: false, reason: "forged" };
  let claim: GateClaim;
  try {
    claim = JSON.parse(Buffer.from(body, "base64url").toString("utf8")) as GateClaim;
  } catch {
    return { ok: false, reason: "malformed" };
  }
  if (claim.exp < nowMs) return { ok: false, reason: "expired" };
  if (claim.cmd !== expect.cmd || claim.argsDigest !== expect.argsDigest) return { ok: false, reason: "args-moved" };
  if (!ledger.consume(claim.nonce, claim.exp)) return { ok: false, reason: "replayed" };
  return { ok: true, claim };
}
```

2. Tokens are estimated from bytes: UTF-8 bytes divided by 4,

```ts
// core/src/cap.ts
import type { CheckResult } from "@hackbuild/spec";

/** Token budget for --detail summary and for every MCP result (D-110). */
export const SUMMARY_TOKEN_CAP = 5000;

/** Deterministic estimate: UTF-8 bytes / 4, rounded up. An estimate, never a tokenizer. */
export function estimateTokens(text: string): number {
  return Math.ceil(Buffer.byteLength(text, "utf8") / 4);
}

export interface Page {
  findings: CheckResult[];
  truncated?: { omitted: number; cursor: string };
}

/**
 * Findings arrive sorted fail first, then warn (CommandResult rule).
 * `render` is the text mirror of one finding; `fixed` is the token cost of
 * the status line, errors and next, which always fit.
 */
export function paginate(
  findings: readonly CheckResult[],
  start: number,
  fixed: number,
  render: (f: CheckResult) => string,
  cap: number = SUMMARY_TOKEN_CAP,
): Page {
  let used = fixed;
  const out: CheckResult[] = [];
  let i = start;
  for (; i < findings.length; i++) {
    const f = findings[i];
    if (f === undefined) break;
    const cost = estimateTokens(render(f));
    if (out.length > 0 && used + cost > cap) break;
    used += cost;
    out.push(f);
  }
  if (i >= findings.length) return { findings: out };
  return { findings: out, truncated: { omitted: findings.length - i, cursor: Buffer.from(String(i)).toString("base64url") } };
}
```

```ts
// core/src/repeat.ts
import type { Verdict } from "@hackbuild/spec";

/** One line of <workspace>/.hbf/calls.jsonl. */
export interface CallLine {
  /** ms since epoch */
  t: number;
  workspace: string;
  branch: string;
  cmd: string;
  inputsHash: string;
  buildHash?: string;
  verdict: Verdict;
  reportHash?: string;
}

export interface RepeatError {
  code: "E_REPEAT";
  hint: string;
  record: string;
}

export const REPEAT_WINDOW_MS = 30 * 60_000;

export function repeatGuard(
  log: readonly CallLine[],
  next: { cmd: string; inputsHash: string; workspace: string; branch: string },
  nowMs: number,
): RepeatError | null {
  const recent = log.filter(
    (l) => l.t > nowMs - REPEAT_WINDOW_MS && l.workspace === next.workspace && l.branch === next.branch,
  );
  const same = recent.filter((l) => l.cmd === next.cmd && l.inputsHash === next.inputsHash);
  if (same.length >= 2) {
    return { code: "E_REPEAT", hint: "same call three times; the inputs did not change", record: "hbf://knowledge/03-diagnostics#same-call-three-times" };
  }
  const fails = recent.filter((l) => l.verdict === "fail" && l.reportHash !== undefined).slice(-4);
  if (fails.length === 4 && new Set(fails.map((f) => f.reportHash)).size === 1) {
    return { code: "E_REPEAT", hint: "four builds failed the same way; the part is wrong, not the parameter", record: "hbf://knowledge/03-diagnostics#wrong-part-not-pose" };
  }
  return null;
}
```
