Goal: Live instruments behind one safe driver contract.
Depends on: M09, M12

## What this milestone proves

link is the one tier 3 package that touches hardware. An offline generator
that is wrong costs filament; a live instrument that is wrong leaves a beam
on (PLAN.md section 9). Every safety behaviour therefore lives in link, in
the lowest layer that can see the failure, and every app and bake inherits
it by importing link.

link is extracted from code the owner already ships and debugged, never
written from a description:

| piece | source of record | what it caught |

3. Add `spec/device.ts`. It holds the device contract that link

   ```ts
   export type TransportKind = "webusb" | "webserial" | "webble" | "webhid" | "http" | "sim";
   export type DeviceStatus = "detached" | "opening" | "idle" | "streaming" | "error";

   /** A write whose rev is not newer than the held rev is ignored. */
   export interface ConfigValue<T> {
     readonly value: T;
     /** Monotonic revision, unitless. */
     readonly rev: number;
     readonly origin: "board" | "host" | "relay" | "snapshot";
   }

   /** Burn limit enforced in the lowest driver. */
   export interface DutyLimit {
     /** Longest continuous on time, ms. */
     readonly maxOnMs: number;
     /** Forced rest after maxOnMs, ms. */
     readonly cooldownMs: number;
   }

   export interface DriverContext {
     emit(artifact: { readonly kind: string; readonly [k: string]: unknown }): void;
     log(message: string): void;
     setInfo(info: Record<string, string>): void;
     isArmed(cap: Capability): boolean;
     /** Cancelled on stop or close; the bus passes its AbortController's signal. */
     readonly signal: { readonly aborted: boolean };
   }

   export interface DeviceSession {
     getCapabilities(): Capability[];
     getInfo(): Record<string, string>;
     describe?(): { readonly params?: readonly unknown[] };
     configure(params: Record<string, number>): Promise<void>;
     start(mode: string): Promise<void>;
     stop(): Promise<void>;
     /** Receive only, beam off, outputs undriven, lines high-z. Runs on every detach. */
     resetToSafeState(): Promise<void>;
     close(): Promise<void>;
     health(): Promise<boolean>;
     /** Board-side arm (SPROCKET `EN 1`): true only when telemetry reports it inside windowMs. */
     confirmArm?(cap: ConsequentialCapability, windowMs: number): Promise<boolean>;
   }

   export interface DeviceManifest {
     readonly firmware: readonly { readonly path: string; readonly sha256: string }[];
     /** Board dead-man window, ms; null when the firmware has none. */
     readonly deadmanMs: number | null;
     /** Host traffic cadence while an output is live, ms. */
     readonly heartbeatMs: number | null;
     /** Present when the device offers fire.laser; values unknown stay null. */
     readonly laser?: {
       readonly classLabel: string | "unknown";
       /** Emission wavelength, nm. */
       readonly wavelengthNm: number | null;
       /** Rated optical output, mW. */
       readonly powerMw: number | null;
       readonly tier: Tier;
     };
     /** Consequential outputs driven inactive before setup() returns. */
     readonly bootSafe: readonly {
       readonly pin: string;
       readonly level: 0 | 1;
       /** file:line where the pin is driven inactive. */
       readonly sourceRef: string;
     }[];
     readonly clasp?: {
       readonly encoding: "msgpack" | "binary";
       readonly streams: readonly {
         readonly address: string;
         /** Largest payload the firmware will publish on this address, bytes. */
         readonly maxPayloadBytes: number;
         /** file:line where the limit is set, for the source cross-check. */
         readonly sourceRef: string;
       }[];
       readonly signals: readonly {
         readonly address: string;
         readonly kind: "param" | "event" | "stream";
         readonly oneShot: boolean;
       }[];
     };
   }
   ```

detaches devices exactly as the bench does, with the bench's failure fixes
carried and named in tests.

Inputs:
- hackbuild-bench/src/core/bus/DeviceBus.ts (417 lines)
- hackbuild-bench/src/core/drivers/types.ts
- hackbuild-bench/src/core/drivers/registry.ts
- hackbuild-bench/src/main.ts lines 22 to 23 (`pagehide` calls `bus.detachAll()`)
- hackbuild-bench/HANDOFF.md (failures and fixes, commits 1c34294, 6ddae18, c7f21a2)
- fab-knowledge:sources/repos/hackbuild-bench-and-ui.md section 2 (device bus, attach order, configure)

Steps:
1. Port `DeviceBus` to packages/link/src/bus/device-bus.ts as a plain
   class with no module singleton; the app constructs one. Keep `live`,
   `drivers`, artifact and event subscriptions, and `providers(cap)`,
   `canProvide(caps)`, `provider(cap)`.
2. `attach(handle)` keeps the bench's seven steps in order: node in
   `opening` with empty capabilities; `attached` fired; a `DriverContext`
   whose `emit` stamps source, seq, monotonic `t` and wall time; `open`
   with an abort check that closes a session opened after a detach and
   throws "`<label>` was let go before it finished opening"; `narrow()`
   from `describe()`; defaults pushed with `configure` (a failure logs
   "defaults not applied" and does not fail open); capabilities read,
   `idle`, health loop started.
3. `configure(id, params)` serialises per device and merges against the
   params the previous call left; on rejection the node's params revert
   and the error fires once per distinct message. The known cost stays
   written in a comment: a configure that never settles blocks every later
   one on that device, detach included. Add a bounded wait so detach is
   not blocked: after 2000 ms (inferred; the bench names no bound) detach
   proceeds and logs the stuck configure.
4. Arming: `arm(id, cap)` is a no-op for observe capabilities, per device
   and per session, cleared on detach. When the session implements
   `confirmArm`, `arm` resolves armed only if telemetry confirms inside
   1200 ms (SPROCKET `sprocket.html` line 866 waits 1.2 s); otherwise the
   node stays disarmed and the log says "board never reported the arm".
5. Health: one interval of 4000 ms while any device is live; false or a
   throw sets `error` with "device stopped responding, it may have been
   unplugged".
6. `detach` aborts, calls `resetToSafeState()` then `close()` with errors
   swallowed, deletes, fires `detached`. `detachAll()` runs every detach.
   `installUnloadStop(bus, target)` registers `pagehide` and
   `beforeunload` on the given EventTarget and calls `detachAll()`;
   T07 extends it with the stop lines.
7. Drivers register through a `DRIVERS` manifest and the `adapters`
   registry (T01 step 4); no switch on device kind anywhere in link.
8. Leave out of link: the bench's Pinia stores, unit memory keyed by
   `hackbuild.bench.units`, playbooks, offers, analysis and every driver
   except CONDUYT and the sim twin generator. rtlsdr stays in the bench
   app (D-094 default); hackrf, ubertooth, meshtastic, pineapple and esp32
   stay there until a fab design needs one.

Files to create:
- packages/link/src/bus/device-bus.ts
- packages/link/src/bus/unload.ts
- packages/link/src/drivers/types.ts (re-exports spec/device.ts)
- packages/link/src/drivers/registry.ts
- packages/link/test/device-bus.test.ts

Acceptance:
- `npm test -w packages/link -- device-bus` -> exit 0 with named cases:
  detach during open closes the late session and throws the let-go
  message; a refused configure reverts params and logs once across ten
  identical refusals; two configures in flight apply in order; arm of an
  observe capability is a no-op; arm with an unconfirmed `confirmArm`
  stays disarmed after 1200 ms of fake time; a health throw sets error
  within one 4000 ms tick of fake time; `detachAll` calls
  `resetToSafeState` before `close` on every live session; a dispatched
  `pagehide` on a test EventTarget detaches all
- `grep -rn "from 'vue'\|from \"vue\"" packages/link/src` -> no output

Done when: a device opens passive, arms per device per session, and is

## M13-T07 Safety layer

Goal: the D-093 rules hold in the lowest layer that can see each failure,
each with a named test, and the UI posture stays one informational confirm.

Inputs:
- fab-work-directory:benches/washer/outputs/PanTiltLaserCLASP.ino lines 96 (`rev` monotonic), 104 to 108 (`maxOnMs`, `cooldownMs`, `jobMaxPts`), 137 to 147 (`driveLaser` burn limit), 247 to 255 (defaults), 299 to 304 (newer rev wins)
- fab-work-directory:benches/sprocket/outputs/sprocket_fw/sprocket_fw.ino lines 53 (disarmed at boot), 714 and 922 (SNAPSHOT received, not executed), 1345 to 1349 (dead-man)
- fab-work-directory:benches/sprocket/outputs/sprocket.html lines 843 (400 ms heartbeat), 866 (1.2 s arm confirm), 1231 (`beforeunload` STOP and EN 0)
- fab-work-directory:benches/washer/outputs/washer.html line 412 (PING every max(300, deadman x 0.5) ms)
- <beam>/packages/beam-link/src/safety.ts, safety.test.ts
- hackbuild-bench/RULES.md Safety posture
- docs/plan/DECISIONS.md D-009, D-093, D-161

Steps:
1. Duty limit in the lowest driver. Every driver offering fire.laser
   carries `duty["fire.laser"]` (CHK-DEV-04) and enforces it inside the
   session's output call: a beam held
   past `maxOnMs` is cut and refused for `cooldownMs`, whatever the caller
   asks. WASHER CLASP defaults 12000 ms on and 3000 ms rest (inferred:
   firmware defaults at `PanTiltLaserCLASP.ino` line 253, no coupon) are
   profile machine rows with that tier, read by the driver. Job size is
   clamped to `jobMaxPts` 1200 (inferred, line 255).
2. Clamp remote input. Every value arriving from a non-local origin
   (relay, snapshot, another tab, a share link) passes through the
   descriptor's bounds before `configure`: NaN and infinities are refused,
   finite values clamp to min and max, choices snap to the nearest allowed
   value. WASHER's `normToUs` is the precedent.
3. Config authority. `ConfigStore` keyed by device uid and key holds
   `ConfigValue {value, rev, origin}`. A write whose rev is not newer than
   the held rev is ignored and logged. Adopt-on-connect writes the board's
   values with origin `board`; host writes increment rev. If nothing
   arrives within 2.5 s of a relay connect, the board copy is republished
   (WASHER CLASP bootstrap).
4. Never execute a replay. A value with origin `snapshot` may update
   config through step 3 and never triggers an action: no move, no output,
   no arm, no job. Commands carried as Events (snap, reboot, cmd) are
   dropped when they arrive inside a SNAPSHOT (SPROCKET and LOUVER
   behaviour).
5. Arm confirmed by telemetry: T03's `confirmArm` window is 1200 ms; the
   UI flips only on confirmation (SPROCKET does not flip optimistically).
   Devices open disarmed; nothing armed survives a reconnect.
6. Stop on unload: `installUnloadStop` sends each live session's stop
   sequence (T08, T09) before `detachAll`, without awaiting between
   devices, because a page in `pagehide` may not finish an async chain.
   The board's dead-man is the backstop on serial, where no disconnect
   event reaches the firmware (INV-46).
7. No blocking reconnect while an output is live: a transport reconnect
   waits until every armed output on that device reads zero (SPROCKET
   dials only with all motor outputs at zero).
8. Heartbeat: while an output is live and no other traffic flows, the
   session sends its keepalive at most every `deadmanMs / 2` ms, with a
   300 ms floor (washer.html rule). This is the rule CHK-DEV-03 checks.
9. Secrets: config keys flagged secret (WiFi password, relay token and
   the T18 relay grant secret) never
   reach the log, the console mirror or an artifact; they display as first
   4 and last 4 characters (D-009). SPROCKET's `***` echo is the firmware
   side of the same rule.
10. The UI posture stays the bench's: passive first, one confirm that
    states what the action does, no lockouts, no policy engine, the user
    is trusted (bench RULES.md). Machine-level dead-man behaviour lives in
    the driver; the app adds no second confirm.

Files to create:
- packages/link/src/safety/duty.ts
- packages/link/src/safety/clamp.ts
- packages/link/src/safety/config-authority.ts
- packages/link/src/safety/replay.ts
- packages/link/src/safety/keepalive.ts
- packages/link/src/safety/secrets.ts
- packages/link/src/bus/unload.ts (edited)
- packages/link/test/safety.test.ts

Acceptance:
- `npm test -w packages/link -- safety` -> exit 0 with one named case per
  rule: beam held 12001 ms of fake time is cut and refused until 15001;
  NaN, Infinity, 1e9 and -1e9 into a 500 to 2500 us field clamp or refuse
  and never reach `configure` unclamped; a rev 4 write after rev 5 is
  ignored; a SNAPSHOT carrying `cmd/snap` and a throttle value produces no
  session call except a config update; arm without telemetry stays off at

Inputs:
- fab-work-directory:benches/detent-beam/outputs/detent_firmware.ino (protocol table, status cadence 150 and 700 ms, dead-man at line 808 to 812, 400-character line guard)
- fab-work-directory:benches/detent-beam/outputs/detent-plot.html (`parseQc`, `streamCmds`, keepalive `?` every 2 s with the beam held)

Steps:
1. Codec, in packages/link/src/codec/detent-text.ts: command builders for
   the 1.3 table (`?`, `V`, `H`, `S`, `M`, `J`, `L`, `E`, `X`, `R`, `B`,
   `G`, `I`, `D`, `N`, `U`, `P`, `A`, `Y`, `W`, `C`, `Q`) and a parser for
   `st` status lines (`q= free= px= py= lx= ly= mx= my= run= drop= rate=

   partial key-value map is ever returned. `S` lines come from motion's
   serialiser; the codec never re-plans. A missing interval omits the
   fourth field, never a trailing comma (INV-18).
2. Classification before anything else: the probe `?` is the only line

   unclassified peer: on a step board `ECHO 0` parses as `E 0` and
   releases both coil sets, `M 1500 1500 0` is an unclamped millimetre
   slam. Accept all three hellos (`detent ready`, `detent 1.3`,
   `BEAM x.y`) and the three BLE names (INV-63).
3. Adopt-on-connect: after classification send `V` then `Q`; fill config

4. Credit window: send a batch of 6 only while `free >= 6 + 8 = 14`; poll

   (one second of no progress); spend locally so six points launched are
   six slots gone before the next report (INV-24). The board reports every
   150 ms while running and every 700 ms idle (INV-28); a lost report is
   recovered by the re-query.
5. Safety: stop is `X` then `L 0` (INV-43); keepalive `?` every 2000 ms
   while the beam is held on manually, inside the 5000 ms dead-man
   (INV-47, firmware line 810), and only while the page is visible and
   focused. Blur, `visibilitychange` to hidden and `pagehide` stop the
   keepalive and send `L 0`, so the 5000 ms board dead-man cuts the beam
   when the operator leaves. The keepalive proves a page is open; this
   rule ties it to a person looking at it; `warn deadman beam off` pauses the job and
   lets the operator resume from where the beam stopped.
6. Board model for tests and the twin, ported from BEAM `mock.ts` step
   lineage: dispatch on the first character of the line exactly as the
   firmware does, so the destructive collisions are provable in a test.
7. Host-side firmware tests are T12; this card links them in the README.

- packages/link/src/drivers/beam/classify.ts
- packages/link/src/drivers/beam/detent-28byj.ts

Inputs:

- <beam>/packages/beam-core/src/protocol/spec.ts, frame.ts, crc8.ts, spec.test.ts
- <beam>/packages/beam-link/src/packet.ts, stream.ts (`PulseCredit`, `streamPulseSegments`, `drainQueue`)
- <beam>/docs/invariants.md INV-12 to INV-17, INV-22, INV-23, INV-25, INV-26, INV-29, INV-35, INV-41 to INV-46, INV-48, INV-59, INV-61, INV-82, INV-83

Steps:
1. Port the codec from BEAM `beam-core/src/protocol` (the most refined
   copy, D-156), keeping its comments that say what each rule cost:
   - flat `A5 | count | seq | [pan16 tilt16 flags dur] x count | crc8`;
   - delta `A6 | count | seq | pan16 tilt16 flags dur | [dpan8 dtilt8
     flags dur] x (count - 1) | crc8`;
   - escape `A7` plus the low nibble for any reserved byte after byte 0;
     legacy flat and delta escape `0xA5` to `0xA7`, hermite escapes from
     `0xA4` (INV-12); byte 0 is never escaped;
   - CRC-8/ATM: polynomial 0x07, init 0, no reflection, no final xor,
     over the unescaped bytes from the magic through the last payload
     byte; a CRC failure keeps the sequence primed (INV-14);
   - count 1 to 10 legacy, 8 hermite (INV-15); flags bit 0 beam gate,
     bit 1 planned (INV-17);
   - the receiver restarts on a magic byte only when no frame is open
     (INV-13, the one inherited defect BEAM fixes; the shipped receiver
     restarts on any magic and loses a good packet when a payload byte is
     0xA4).
   The hermite (0xA4) and step (0xA3) formats are ported with the rest
   and used only when the board advertises them in its wire caps; a
   field board flashed with the shipped `PanTiltLaser.ino` negotiates
   flat and delta only.
2. Driver connect: classify with `?` first (T08 step 2), then `ECHO 0`,

Goal: both codecs round trip over a seeded lossy transport, and every

1. `LossyTransport` wraps the mock with a seeded PRNG (32-bit, seed in
   the test name) and per-direction options: drop a byte, drop a whole
   BLE write (20 or 180 bytes), flip a bit, splice the head of one write
   onto the tail of the next, delay a write by up to N ms, disconnect at
   t. Faults are logged with offsets so a failing seed replays exactly.
2. WASHER cases, 1000 seeds each (computed by the test, not sampled):
   - with byte drops at 1 per 500 bytes, every decoded packet's CRC
     passed and no packet is half applied. The shipped firmware's claim
     is that one lost byte costs one packet. Under the INV-13 framer an
     open frame does not restart on a magic byte, so a byte lost inside
     packet k can also swallow the opener of packet k + 1 until the
     length or the 250 ms idle close ends the frame (inferred from
     `frame.ts`, not measured). The test asserts at most two packets
     lost per dropped byte and writes the observed ratio to the golden;
     a ratio above 1 is reported to the BEAM owner with the seed;
   - with bit flips at 1 per 2000 bytes, no flipped packet is applied
     (CRC-8 0x07 catches every single-bit error, computed);
   - splices are rejected by CRC or by length;
   - the decoder's lost-segment count equals the sequence gap the
     transport caused;
   - after a 250 ms silent gap mid-frame, the next packet lands clean.
3. DETENT cases, 1000 seeds each:
   - dropped status lines never wedge the stream: the 25-poll re-query
     recovers credit and the job completes;
   - a rx line with a flipped byte that breaks the grammar is rejected
     whole; one that stays grammatical is applied as read (the text
     protocol has no checksum; the BLE link layer is the integrity
     check, and the README states this as a limit);
   - dropped tx `S` lines leave the board short and the host notices
     through `free=` and position, never silently.
4. Dead-man cases on both: the transport goes silent with the beam lit
   and the queue empty; the model cuts the beam at 1500 ms (WASHER) and
   5000 ms (DETENT); with the queue non-empty it does not (INV-41).
5. Any seed that fails is copied into `packages/link/test/seeds.json`
   with the fault log before it is fixed, so it stays a regression.

   ```ts
   /** MessagePack str header length for a string of n UTF-8 bytes. */
   export function mpStrHeader(n: number): number {
     if (n < 32) return 1;
     if (n < 256) return 2;
     if (n < 65536) return 3;
     return 5;
   }

   /** UTF-8 byte length without TextEncoder, so the module needs no DOM or node lib. */
   export function utf8Length(s: string): number {
     let n = 0;
     for (const ch of s) {
       const c = ch.codePointAt(0) ?? 0;
       n += c < 0x80 ? 1 : c < 0x800 ? 2 : c < 0x10000 ? 3 : 4;
     }
     return n;
   }

   /**
    * Bytes a MessagePack stream PUBLISH spends around its bin payload, as LOUVER
    * clasp.h encodes it: map4, "type":"PUBLISH", "address":<addr>,
    * "signal":"stream", "value":bin16. 45 fixed bytes plus the address string.
    * At "/louver/1/frame" this is 61.
    */
   export function claspStreamPublishOverhead(address: string): number {
     const n = utf8Length(address);
     return 45 + mpStrHeader(n) + n;
   }

   /** The CLASP frame payload length is a uint16. */
   export const CLASP_MAX_PAYLOAD = 65535;

   export function claspStreamPayloadCeiling(address: string): number {
     return CLASP_MAX_PAYLOAD - claspStreamPublishOverhead(address);
   }
   ```

the same as a BLE line. A `CFG clasp.base` from the relay moves the

Steps:
1. Origin on every inbound message. The bus carries
   `MessageOrigin` (`local`, `board`, `host`, `relay`, `snapshot`) on
   each message. Only code under `packages/link/src/transport/` sets it;
   any relay client (none ships at M13, see the CLASP SDK row below) and
   the mock relay source tag `relay`. Add to spec/device.ts:

   ```ts
   /** Where an inbound message came from. Only transport code sets it. */
   export type MessageOrigin = "local" | "board" | "host" | "relay" | "snapshot";

   /** Transports a relay grant may be issued on: a person is at the device. */
   export type DirectTransport = Extract<TransportKind, "webusb" | "webserial" | "webble">;

   /**
    * Admits relay-origin consequential messages for one device while its arm
    * lasts. Issued at arm time on a direct transport; voided when the arm ends.
    */
   export interface RelayGrant {
     readonly deviceUid: string;
     /** Consequential capabilities this grant admits from a relay origin. */
     readonly caps: readonly ConsequentialCapability[];
     /** 128 random bits as 32 hex characters; a secret under D-009; never sent on a relay. */
     readonly secret: string;
     /** Highest accepted relay sequence for this grant, unitless. */
     readonly lastSeq: number;
     readonly issuedOn: DirectTransport;
     /** Arm generation the grant belongs to, unitless; disarm, detach and reconnect bump it. */
     readonly armGeneration: number;
   }

   /** Relay authentication a device's firmware supports. */
   export type RelayAuth = "mac" | "none";
   ```

   `DeviceManifest` gains `relayAuth: RelayAuth`, default `none`.
2. Issue at arm, on a direct transport only. When an arm of a
   consequential capability is confirmed by telemetry (T07 step 5) on

   grant (sim twins mint one only under the test flag). An arm request
   that itself arrives from a relay origin is refused with E_GATE: the
   relay cannot mint the secret that gates it.
3. Expire with the arm window. The grant is void on disarm, detach,
   transport reconnect, a lost arm confirmation, a dead-man trip and

   survives a reload (T07 step 5: devices open disarmed). The arm

   public relay sees every frame (cheatsheet line 124 below). For
   `relayAuth: "none"`, link refuses to publish
   a consequential command to the relay with E_GATE and offers the

7. Failure record. Add section `relay-base-path` to
