## What this milestone proves

A part can come from a BRep: a STEP file a person brings, or a short
replicad program in build.ts for the shapes the restricted vocabulary
lacks (sweeps, lofts, fillets on arbitrary edges). The archetypes and
feature kinds written for kernel parts apply to that part unchanged, the
check registry proves it from Part IR exactly as it proves a kernel part,
and the result leaves as STEP through the same export gate as every
fabrication format. The route stays opt-in: it is never a model's default,
never in the default offline bake, and its wasm loads only when a part
declares `route: "brep"` (D-024).

|---|---|---|
| replicad 1.1.0 absent from the default bake | loader trap over every non-brep reference; bundle and bake scans; size fact | M14-T09 |
| LOCKET STEP imports | the LOCKET R2 body as STEP, two solids, volumes and face counts in a golden | M14-T03 |
| STYLUS dome applies to its lid face | `arch.apply` of `dome-button` on the LOCKET lid floor face, resolved by face query | M14-T06, M14-T07 |
| every check runs unchanged on Part IR | same selected check ids and versions as the prism baseline; no diff under packages/checks/src | M14-T07 |

Five findings shape the cards. The LOCKET body has no STEP, so the
milestone makes a faceted one from the shipped mesh and says so in every
README that uses it. replicad's own `importSTL` fails in Node, so the
fixture path calls the OCCT classes directly. The STEP writer stamps the
wall clock into FILE_NAME and prints to stdout, so the exporter rewrites
the header and the module routes its console. Memory grows with operand
size on every boolean even with explicit `delete()`, fast enough on a
2713-face solid to kill a process within 800 operations, so the route
runs in a recyclable instance with a memory ceiling (M14-T05). The kernel
wasm alone (22,980,267 B) is larger than the 16 MB bake ceiling of D-129,
so the default bake could not carry it even by mistake; T09 proves the
bake carries none of it anyway.

## M14-T01 Wire replicad behind a lazy entry

Goal: the OCCT kernel loads in Node and in the browser only through one
lazy entry in packages/mesh, with pinned versions, routed console output
and recorded licences.

Inputs:
- `fab-knowledge:research/code-cad-and-eda-tooling.md` section 3.4 (replicad, opencascade.js, brepjs) and lines 34 to 45 (tool table)
- `fab-knowledge:evidence/x/m14/probe.mjs`, `probe2.mjs`, `probe5.mjs`
- packages/mesh (M00), spec/registry.ts BuildInputs, spec/ids.ts MeshRoute
- D-024, D-040, D-041, D-043, D-051

Steps:
1. Add `replicad` 1.1.0 and `replicad-opencascadejs` 1.1.0 as exact pins to
   packages/mesh `dependencies`. In the published kernel, list both under
   `peerDependencies` with `peerDependenciesMeta` optional, so a consumer
   that never uses the route installs neither. The second pin is not in
   D-040's table; list it in the PR body and in PLAN.md section 16 when
   the table is re-dated at exit.
2. Write `packages/mesh/src/routes/brep/load.ts` exporting one async
   function `loadBrep(): Promise<BrepKernel>`. It runs
   `await import("replicad-opencascadejs")` and `await import("replicad")`,
   creates the module with `locateFile` pointing at
   `replicad_single.wasm`, and passes `print` and `printErr` handlers that
   append to a bounded log the route returns in its warnings. Nothing from
   OCCT reaches stdout, so `--json` output stays one JSON document.
   `setOC` is called once per instance.
3. Use the single-threaded build. The multi-threaded build needs
   SharedArrayBuffer and cross-origin isolation, which neither the CLI's
   determinism job nor a file:// page can count on.
4. Record in BuildInputs (D-051): `engines.replicad: "1.1.0"`,
   `engines.occt: "replicad-opencascadejs 1.1.0"` (the STEP header names
   OCCT 8.0, observed), and licences `replicad: MIT`,
   `replicad-opencascadejs: LGPL-2.1-only`. These enter BuildInputs only
   for builds whose parts use the route, so no existing buildHash moves.
5. Ship the wasm as its own file next to the code that loads it, never
   inlined into a JS chunk, so it stays a separate, replaceable work under
   LGPL-2.1 (D-043). Add the row to LICENSING.md, and add an opentype.js 1.3.4 (MIT) row to tools/licences.json, since replicad 1.1.0 pulls it in for glyph outlines.
6. Smoke test in `packages/mesh/src/routes/brep/load.test.ts`: box
   10 x 20 x 30 volume 6000; the filleted box of the Records table
   5965.663706 mm3 within 1e-6 and 10 faces; STEP export then import of the
   box returns volume 6000 within 1e-9; nothing written to stdout during
   the test.
7. Record replicad's `importSTL` failure as a test that asserts it still
   throws (`it.fails` style, named `replicad-importSTL-throws`). When an
   upgrade makes it pass, the test fails and the upgrade PR decides whether
   to switch to it. The route uses the T03 path in the meantime.

Files to create:

- packages/mesh/src/routes/brep/load.test.ts
- packages/mesh/src/routes/brep/README.md (what the route guarantees, D-053; what it refuses)
- LICENSING.md row for replicad and replicad-opencascadejs (edit)
