## Package placement

`tools/tiers.json` puts `reference` in tier 2 with an empty `sameTier`
list (M-1-T12). `reference` may import `spec`, tier 0 and tier 1. It may
not import `checks`, `chase`, `project` or `knowledge`, which share its

| need | how it is met without a same-tier edge |
|---|---|
| the set of registered checks, kinds, canon entries, exporters | `core` reads each registry and passes plain `CoverageItem[]` into `reference` (registration by inversion, D-044) |

normaliser, the coverage computation, and the renderers. `core` owns:

## The covers grammar

Earlier cards wrote covers ids in four spellings: `export:3mf` and
`route:raster` (M00-T11), `'feature:inlay'` with bare `'CHK-INL-01'`
(M03-T08), bare mechanism ids (M06-T06), and free text such as `read
pullup` and `circuit.solve` (M05-T07, M05-T11). M11 fixes one grammar.

| namespace | form | counted toward closure | evidence that proves it on the live build |
|---|---|---|---|
| feature | `feature:<FeatureKind>` | yes | the Part IR has at least one feature of that kind |
| check | `check:<CHK id>`; a bare `CHK-XXX-NN` normalises to this | yes | the report holds a result for the id with verdict pass, or fail inside a declared expect set (D-074); skip never counts |
| mechanism | `mechanism:<id>` | yes | the registry entry's `reference` field names this reference (two-way link) |
| archetype | `archetype:<id>` | yes | the registry entry's `reference` field names this reference (two-way link) |
| kind | `kind:<ChaseKind>` | yes | `chase.meta.kind` equals the id |
| export | `export:<exporter id>` | yes | `chase.exports` declares the id and `expected/artifacts.json` holds a hash for it that the parity run reproduces |
| route | `route:<MeshRoute>` | no | a body was made by that route (D-053) |
| read | `read:<ReadModel>` | no | a port feature declares that read model (D-078) |
| command | `command:<CommandName>` | no | the name is one of the 30 of D-106 |
| constraint | `constraint:<ConstraintDef id>` | no | the id is registered |
| board | `board:<board feature>` | no | the id is in the D-061 namespace |

Informational namespaces are validated (an unknown id is E_REF) and shown
by `reference.list`, but they never satisfy the coverage rule. A reference
must list at least one counted id.

The covers list lives in chase.ts as a named export beside the chase, so
changing covers never moves `defHash` (which hashes the canonical chase
object and build.ts bytes, D-051) and never churns a golden. If spec/ at
M11 start defines a different home for covers, spec wins and M11-T01 moves
every reference to it in one PR.

```ts
// reference/<area>/<id>/chase.ts, beside `export const chase = defineChase(...)`
export const reference = {
  covers: ["feature:inlay", "check:CHK-INL-01", "check:CHK-INL-03", "export:3mf", "route:raster"],
  admittedIn: "M03",
  source: { design: "COLLAR", evidence: "fab-work-directory:benches/collar-coin/" },
} as const satisfies ReferenceMeta;
```

## The coverage types

The shape below was type-checked on 2026-10-04 with TypeScript 7.0.2
(`tsc --strict --noUncheckedIndexedAccess --exactOptionalPropertyTypes`,
exit 0) against local stand-ins for the spec unions; the `source` union
with `record` and `portsFrom` was re-checked the same way on 2026-10-05
(exit 0, one meta with each source form). spec/ wins on every
name it defines; the PR lists each difference.

```ts
export type CoverageClass = "feature" | "check" | "mechanism" | "archetype" | "kind" | "export";
export type InfoClass = "route" | "read" | "command" | "constraint" | "board";
export type CoversId = `${CoverageClass}:${string}` | `${InfoClass}:${string}`;

export interface ReferenceMeta {
  /** Ids this reference proves; at least one counted entry. */
  covers: readonly [CoversId, ...CoversId[]];
  /** Milestone whose card wrote it (MILESTONES.md Part 3 rule 5). */
  admittedIn: Milestone;
  /** Legacy design with an absolute evidence path, or the decision a minimal reference was written from.
   *  `record` and `portsFrom` are required when the design is one of the originals (D-222). */
  source:
    | { design: string; evidence: string; record?: `knowledge/designs/${string}.md`; portsFrom?: string }
    | { design: null; decision: string };
}

export interface CoverageItem {
  cls: CoverageClass;
  id: string;
  state:
    | { kind: "admitted" }
    | { kind: "gap"; status: "stub" | "candidate" | "unproven"; reason: string; unblocks: string }
    | { kind: "scheduled"; lands: Milestone; reason: string };
}

export interface ReferenceRun {
  ref: string;                       // "<area>/<id>"
  meta: ReferenceMeta;
  green: boolean;                    // M11-T03
  failures: readonly string[];
  evidence: {
    featureKinds: ReadonlySet<string>;
    checks: ReadonlyMap<string, { verdict: "pass" | "fail" | "skip"; expected: boolean }>;
    chaseKind: ChaseKind;
    exports: ReadonlySet<string>;
    artifactKinds: ReadonlySet<string>;
  };
}

export interface CoverageRow { item: CoverageItem; coveredBy: readonly string[]; claimedBy: readonly string[] }
export interface CoverageReport {
  rows: readonly CoverageRow[];
  uncovered: readonly CoverageItem[];                      // empty at exit
  dangling: readonly { ref: string; id: CoversId }[];      // empty at exit
}
```

`coveredBy` lists green references that name the item and whose evidence
proves it. `claimedBy` lists references that name the item without proving
it; a non-empty `claimedBy` on any row fails the test, because a covers
entry the build does not back is a false statement in the library.

## Universe and gap rules

The coverage test derives the universe at run time. A list typed into the
test would be a hand-maintained list another file determines (CHK-LNT-03,
D-010).

| class | universe source | admitted | gap (allowed, listed with reason) | scheduled (allowed, lands after M11) |
|---|---|---|---|---|
| feature | `FEATURE_KINDS`, a const array in spec/features.ts asserted equal to the `FeatureKind` union by a type test; 22 solid kinds plus the eight of D-059 (30 expected, computed from PLAN.md 6.2 and 6.3) | every member | none: a kind cannot be admitted without a reference (D-058, D-177) | none |
| check | the check registry (M04) | every entry whose skip reason is null on the full M11 kernel set | none | entries with `pending` naming M12 or later (CHK-DEV-01 to -03 land M13, M04-T12) |
| mechanism | the mechanisms registry (M06) | status typed | stub, candidate, unproven, with the reason and unblock fields the registry carries | none |
| archetype | the archetypes registry (M06, M08, M10) | status proven | stub, candidate, unproven, as above | none |
| kind | `ChaseKind` in spec/chase.ts (six, D-126) | every member | none | none |
| export | the exporter registry (`ExporterDef`, D-132) | every registered id | none | ids a later milestone registers (`step` lands M14, D-160) appear only after they register |

Rules the test enforces beyond `uncovered` and `dangling`:

1. A gap row's reason and unblock text come from the registry entry. A gap
   with an empty reason fails.
2. A scheduled check whose `pending` names M11 or earlier fails: every
   kernel and target it needs exists by M11 (M04-T01 skip table: the last
   kernel, board, lands M08; page targets land M09).
3. Every `FeatureKindDef.reference`, `MechanismDef.reference` and
   `ArchetypeDef.reference` id resolves to a folder under `reference/`,
   and that reference's covers names the entry back. A one-way link fails.
4. A reference whose `admittedIn` is later than the milestone in which its
   first covered item was admitted is allowed only with a line in
   COVERAGE.md naming why (for example a kind admitted in M-1 spec whose
   reference waited for M11, D-058).
