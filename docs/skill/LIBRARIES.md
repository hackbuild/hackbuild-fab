# hackbuild bench libraries 0.3.0

Generated by tools/skill-kit/reference.mjs from the built files and types. Do not edit by hand; `npm run skill:reference` rewrites it and a test fails when it is stale. Release tag `lib-v0.3.0`, base `https://cdn.jsdelivr.net/gh/hackbuild/hackbuild-fab@lib-v0.3.0/`.

A bench page loads these libraries and writes only what belongs to its design: its chase, its bench declaration, its build. It carries no mesh kernel, no 3MF writer and no bench shell of its own. `node tools/skill-kit/check-page.mjs <page.html>` refuses a page that does.

## The engine

`@hackbuild/engine` is the build half of a bench. It carries the kernel a page runs: geom, mesh, inlay, the checks, the profile data and the 3MF writer. A page that loads it writes a chase and a build function and gets geometry, check results and 3MF, STL and card exports, with no bake step and no mesh kernel of its own.

`createPageBuild({ chase, module, facts })` returns a page build. `module` is an object holding the build function under the name `chase.build.fn` names. `pageBench(page)` from `@hackbuild/bench` turns the page build into the `build` and `writers` options of `createBench`.

```ts
export interface PageInput {
    readonly chase: Chase;
    /** The build.ts module namespace; chase.build.fn names the build function in it. */
    readonly module: Readonly<Record<string, unknown>>;
    readonly kinds?: DraftKinds;
    readonly facts: PageFacts;
    /** An hbf draft page (plan v9 3.1): fails show as warnings and every export carries the DRAFT marks. */
    readonly draft?: boolean;
}

export interface PageBuild {
    readonly chase: Chase;
    readonly facts: PageFacts;
    /** True on an hbf draft page; the ui names its downloads with DRAFT_ from it. */
    readonly draft: boolean;
    /** Builds and checks one set of values; the values are resolved against the chase as part.build resolves them. */
    build(values: Values): Promise<PageResult>;
    /** Writes one export from a build this page made, by its buildHash. */
    exportFile(kind: PageExportKind, buildHash: string): Promise<PageFile>;
    /** Owned wasm objects alive between builds, count; zero after every build (D-055). */
    liveCount(): number;
}

/** One in-page build with its check run. */
export interface PageResult {
    readonly buildHash: string;
    /** BuildInputs.registryHash of this build, the one `hbf part.build` stores. */
    readonly registryHash: string;
    readonly part: Part;
    readonly meshes: Readonly<Record<string, PageMesh>>;
    readonly metrics: readonly Metric[];
    readonly results: readonly CheckResult[];
    readonly warnings: readonly BuildWarning[];
}
```

`factsFor(chase, source)` computes in the page what tools/bake/design-facts.mjs computes in node: the profile tables, the check seed, the kernel and manifold versions, the constraint versions, the epoch (315532800 unless given) and a defHash. Every field but defHash is equal to the bake's for a design without draft kinds. defHash covers the chase and the sha256 of the source text the page passes, where the bake hashes the design's files on disk, so a page's build hash differs from the golden of the same design. Mesh hashes and volumes are equal. When a page passes the files core's source closure names (`{ "build.ts": text, "chase.ts": text }`) defHash is equal too. A chase that names a machine or material the profile lacks is refused with E_REF and the closest id.

```ts
export interface FactsOptions {
    /** SOURCE_DATE_EPOCH for the build, s; below DEFAULT_EPOCH it is raised to it, as core raises it. */
    readonly epoch?: number;
    /** The 3MF object name and file stem; default the chase's meta.id, which is the folder name of a design. */
    readonly name?: string;
}

/**
 * The source text of a page's build: one string for a single build script, or
 * a record of path to text when the page carries several modules. A path is
 * relative to the design folder, forward slashes.
 */
export type PageSource = string | Readonly<Record<string, string>>;

/**
 * PageFacts for a chase and the text of its build source. The tables are the
 * full profile, which is what core's loadDesign gives a design without draft
 * kinds and what the page build meshes on. defHash covers the chase and the
 * sha256 of each source text, so an edit to either moves it. It equals core's
 * defHash when the page passes the files core's source closure names (the
 * build module and what it imports, by relative path), and differs otherwise.
 */
export declare function factsFor(chase: Chase, source: PageSource, options?: FactsOptions): PageFacts;
```

`defaultKinds` is the feature kinds a chase gets from the kernels it lists in `meta.kernels` (`kernelKindsOf(chase.meta.kernels)`): `circuit`, `inlay`, `mesh`, `nest` register kinds.

One manifold instance serves the page. `manifold-3d` 3.5.4 is a peer: the import map names it (`manifold-3d` above) and the engine reads the wasm beside it. The classic script form carries the glue and takes the wasm bytes through `HackbuildEngine.configureManifold({ wasmBinary })` before the first build; "save offline" writes that call with the wasm inlined. Every library that bundles geom (bench-core does) reads one shared state on the page, so `adoptManifold` through one library and a build through another act on one instance.

Load order of the classic scripts for a page that builds, derived from the sidecars: `vue`, `pinia`, `three`, `@hackbuild/spec`, `@hackbuild/engine`, `@hackbuild/viewer`, `@hackbuild/bench-core`, `@hackbuild/bench`.

## Writing a build

A build is a function from the params to a part draft: `defineBuild(chase, (p, k) => part)`. `p` is the params object the chase declares, typed from the chase; `k` is the author. The function is plain data in, plain data out and runs in the page. A chase declares and never computes; conditionals and loops belong in the build.

```ts
/** Ties a build function's params to its chase. Identity at runtime. */
export declare function defineBuild<const C extends Chase>(_chase: C, fn: BuildFn<ParamsOf<C>>): BuildFn<ParamsOf<C>>;

/** What build.ts exports: params in, declarations out, typed at milestone M. */
export type BuildFn<P, M extends KindMilestone = "M16"> = (params: P, k: Author<M>) => BuildResultAt<M> | Promise<BuildResultAt<M>>;
```

### The author calls

The page build and the hbf CLI run the same calls: `k.ring.offset` through geom's CrossSection, `k.art` through the inlay lowering, `k.path.flatten` and the `k.ring` tests through geom. function markTransform(at: readonly [number, number], span: number): [number, number, number, number, number, number] {
```ts
  const [x0, y0, w, h] = MARK.viewBox;

  const cx = x0 + w / 2, cy = y0 + h / 2;
  return [s, 0, 0, -s, (at[0] - cx) * s, -(at[1] - cy) * s];
```

```ts
// art slot, each carrying the whole art, both faces, under its content
// address (packages/inlay/src/kind.ts artUri), as cosmetic/coin-inlay does.

// art-layers.test.ts (spec/art.ts, lowered by packages/inlay/src/
// art-lower.ts): a build.ts may import only spec, so it writes the
// painter layers as data, and that test holds them equal to the document.

// Front face as read in hand, three rows of six cells (pitch 16 mm by 20 mm
// at the default): row 1 ring, rect, ellipse, frame, diamond, chevrons;
// row 2 grid, sun, saguaro, mesa, zigzag, steps; row 3 arrow, scope,
// circuit, the hack.build mark and a line of text across the last two
// cells. Back face: two arcs of text, spaced text and an arrow. Slots
// alternate 2 and 3 along each row, so every kind paints at least once and
// each art slot has islands on both faces.

import { canonicalize, commandError, defineBuild, sha256Hex, type FaceFrame } from "@hackbuild/spec";
import { chase } from "./chase";

/** Slots the art paints. */
const SLOT = { body: 1, pink: 2, cream: 3 } as const;

/** The face the text is set in: a family the node text route carries, bold. */
const TEXT = { font: "IBM Plex Mono", bold: true } as const;

const SHAPES = [
  ["ring", "rect", "ellipse", "frame", "diamond", "chevrons"],
  ["grid", "sun", "saguaro", "mesa", "zigzag", "steps"],
  ["arrow"],
] as const;

export const build = defineBuild(chase, (p, k) => {
  const m = k.machine("ffc5p");
  const layers = Math.round(p.depth / m.layerHeight);
  if (layers < 1 || Math.abs(layers * m.layerHeight - p.depth) > 1e-6) {
    throw commandError({
      code: "E_SCHEMA", path: "/depth", got: p.depth, expected: `a whole number of ${m.layerHeight} mm layers on ${m.id}`,

    });
  }
  const pitchX = (p.w - 4) / 6, rowY = [20, 0, -20] as const;
  if (p.size + 2 > pitchX || p.h / 2 < rowY[0] + p.size / 2 + 1) {
    throw commandError({
      code: "E_SCHEMA", path: "/size", got: p.size, expected: `shapes inside their cell: under ${(pitchX - 2).toFixed(1)} mm across and ${(2 * (p.h / 2 - 1 - rowY[0])).toFixed(1)} mm tall`,
      hint: "make the shapes smaller or the plate larger",
    });
  }
  const cx = (c: number): number => -p.w / 2 + 2 + pitchX * (c + 0.5);
  const S = p.size, t = p.stroke;
  const plate = k.body("plate", { role: "body", slot: SLOT.body, material: "petg", base: { route: "prism", outline: [k.ring.roundRect(p.w, p.h, 2)], z: [0, p.thk] } });

    const w = name === "saguaro" ? 0.86 * S : S, h = name === "ellipse" ? 0.7 * S : name === "arrow" ? 0.55 * S : S;
    const stroke = name === "grid" ? 0.8 : name === "sun" ? 1.4 : t;

  };
```

## createBench

`createBench(options)` from `@hackbuild/bench` returns a controller. `controller.mount(el)` draws the shell; `controller.core` is the headless bench core. Effects outside the mount element are opt-in and default off.

## The BENCH hook

`createBench({ hook: true })` defines `BENCH` on globalThis. A page without it is refused by check-page.

```ts
export interface BenchHook {
    /** True once the first build finished and the hook is safe to drive. */
    readonly ready: boolean;
    /**
     * Getter returns the design; setter replaces it and rebuilds. A value
     * outside a declared range or option set is clamped to the range (an
     * enum or slot falls back to its default) and each clamp appends a log
     * line naming field, value and range within 100 ms (G-10, P-07):

    /** The last built model. */
    readonly model: unknown;
    /** Increments on every commit, count. */
    readonly rev: number;
    /** rev of the last completed build, count. */
    readonly built: number;

    readonly busy: boolean;
    /** Build hash of the last completed build, null before the first. */
    readonly buildHash: string | null;

     * stage keeps the last good mesh and the status strip shows an error chip

    readonly error: string | null;
    readonly log: string[];

     * `build failed: <error>` when the build for the current rev throws, and
     * with `not settled after <timeoutMs> ms` on timeout. timeoutMs in ms.
     */
    settled(timeoutMs?: number): Promise<void>;
    /**
     * Merge onto a fresh blank, drop retired keys, clamp to declared ranges
     * with one log line per clamp (as the state setter), then commit. Text
     * that is not a design for this bench leaves the design untouched, sets
     * `error` and logs the reason; it never throws to the page or opens an
     * alert (G-37).
     */
    loadDesign(json: string): void;
    designJson(): string;
    ensureMesh(): Promise<void>;
    commit(): void;
    /**
     * Drive pad stimulus: hold a key, slide a pot, tilt a stick. value is a
     * boolean for hold, a number in the target's unit for slide (mm) or a
     * one-axis tilt (degrees), and { tiltDeg, phiDeg } for a stick (P-06).
     * Calls the same ContactFn as the pad, the 3D pose and the readout
     * (DriveDecl.contact, G-20). The stimulus stays applied until release.
     */
    drive(target: string, value: DriveStimulus): Promise<DriveReadoutRecord>;
    /** Release one held target, or every held target when none is named; resolves once the pad is idle (P-06). */
    release(target?: string): Promise<void>;
    /**
     * Base64 bytes of a declared export; kind resolved through EXPORT_ALIASES.
     * Awaits ensureMesh first (G-46). A kind the bench does not declare
     * rejects with an Error whose message is UNKNOWN_EXPORT_KIND followed by
     * the kind, never a TypeError (G-51).
     */
    exportBytes(kind: string): Promise<string>;
    /** Design extras: firmware, wiringSvg, printCard, setTilt. */
    readonly verbs?: Readonly<Record<string, (...args: readonly unknown[]) => unknown>>;
```

## Export path and self-check

The export kinds a chase declares (`json`, `3mf`, `stl`, `card`) write through `BenchOptions.writers`; `pageBench(pageOf(globals.page))` supplies the 3mf, stl and card writers of a design page build, which run the build and every check and refuse a blocking fail with the export gate's line. A fabrication export also needs the host's approval; no argument opens that gate.

Before the shell hands a 3mf to a download it runs `assertExportable("3mf", bytes)` from `@hackbuild/bench-core`. The rules, ported from tools/py/validate_3mf.py:

- `3mf-zip`: the package is a readable zip with at least one .model part.
- `3mf-id`: object ids are unique in each model part and every item and component reference resolves (CHK-3MF-06).
- `3mf-uuid`: every `p:UUID` is unique across the package.
- `3mf-name`: object names are non-empty, carry no unresolved token and are unique (CHK-ART-01).
- `3mf-manifold`: every mesh has two faces per undirected edge, one use of each directed edge and positive signed volume (CHK-PRT-01).

A failing rule refuses the download and the log names it. The same functions are exported for a page's own use:

```ts
export type SelfCheckRule = "3mf-zip" | "3mf-id" | "3mf-uuid" | "3mf-name" | "3mf-manifold";
```
