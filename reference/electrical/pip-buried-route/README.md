# electrical pip-buried-route

The M05-T10 reference (D-084, D-085, C-06): PIP's buried trace stack. The
default layout of PIP at hackbuild/pip-controller b137deb (D-013) is routed
by packages/copper, emitted as two buried conductive PLA trace layers with
their terminal posts and vias in a PETG body on the profile stack rows,
built through the kernel stages, and checked by `circuit.solve` on the
nets it extracts from the built bodies.

covers: [CHK-NET-01, CHK-NET-02, CHK-NET-11, CHK-NET-12, command:circuit.solve, feature:conductor]

## Scope

- The stack is PIP's (pip-controller src/layout.js line 27, print card
  "fits and clearances"): skin 0.72, trace layers 0.72, isolation 0.96,
  PETG over layer 2 1.68 mm on the 0.72 pad floor, trace width 1.40 mm,
  every one a profile row of tier inferred (PROFILE.md 6.1). Bleed is the
  profile default 0, inferred, applied once at emit (D-084), so the
  emitted trace is 1.40 mm wide.
- Only the trace stack is built: the route's layer regions, the terminal
  posts up to the pad plane and the vias. PIP's buttons, click-spring
  floor pads, bumps, cups and bezel belong to the PIP canon (M06). PIP's
  own net check reads 0.59999999 mm on its default model between GND and
  X, B, Y and A, the click-spring floor pads split by 0.60 (computed by
  PIP b137deb, `packages/copper/test/fixtures/pip-sweep-seed1/default.json`);
  those pads are not here, so this stack's closest pair is a trace pair.
- The z stack follows PIP's 0.24 mm grid from the bed, not the ffc5p
  first layer of 0.25 mm, so the part top at 4.82 mm (the terminal posts'
  0.02 mm overlap past the floor, PIP's EZ) reads CHK-PRT-05 warn.

## What is in this folder

| file | what it holds |
|---|---|
| `chase.ts` | the PETG body and cPLA trace slots and one param, `iters`, the router's iteration cap (PIP's 24) |
| `route.data.ts` | generated by `node packages/copper/scripts/pip-buried-route.mjs --write`: the PIP default layout from the M05-T08 fixture routed by `route()` (default mode, Float64), one run per distinct result over caps 1 to 24, each emitted by `emitTraceLayers` on the profile stack, with the route's gated metrics and warnings; never edited by hand |
| `build.ts` | places the data: the body on PIP's outline from the bed to the floor, each layer region and post as a conductor feature, the route metrics (CHK-NET-12) and warnings, the stack as informational metrics; it refuses data generated against other profile values (E_STALE) |
| `queries.json` | the `circuit.solve` golden |
| `expected/` | parity goldens written by `npx --no-install hbf parity reference/electrical/pip-buried-route --accept` at SOURCE_DATE_EPOCH 315532800: `build.json`, `report.json`, `edit.json` (iters 24 to 1, hand-declared pointer), `artifacts.json` (empty, stl only), `query-solve.json` |
| `test/reference.test.ts` | holds route.data.ts to the package, the goldens to the card and to PIP's own model, and the forced failure |

The router lives outside the build module because a build imports only
`@hackbuild/spec` and relative files (D-178); the data test reruns the
generator and fails when the committed module differs.

every conductive body by `3mf.coincidenceInset` (0.001 mm, inferred) on
each side.

### Measured on a printed body

None. Nothing here was printed, sliced or measured; PIP's print card

### Checked by machine on geometry

`expected/report.json` holds the part checks on the body and its 76
conductor bodies; CHK-PRT-05 warns on the 4.82 mm part top (PIP's 0.24 mm
grid from the bed against the ffc5p 0.25 mm first layer). The
`circuit.solve` golden holds CHK-NET-01, -02, -11 and -12 on the nets
extracted from the built meshes.

### Not verified by anything

- Conduction or isolation of any printed trace: the resistivity rows and
  the stack rows are inferred, and bleed 0 waits for a coupon (D-084).
- PIP's button geometry (flex columns, click-spring floor pads, touch
  combs, board bumps), which sets PIP's own 0.60 mm closest pair.
- The ffc5p slice of this stack.
